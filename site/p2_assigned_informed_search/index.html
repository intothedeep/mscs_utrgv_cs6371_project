과제 프로젝트 2: 먹이 찾기 군집을 위한 정보 기반 탐색
Assigned Project 2: Informed search for foraging swarms

결론: 설계와 계획은 끝났다. 1단계(M1) 도구를 작성 중이다. 실제 결과는 아직 없다.

왜 하나: 로봇 군집(swarm)이 아무도 찾지 않은 곳을 서버(server)가 빠르게 알려 주면, 12분 안에 먹이를 더 모은다.

1 과제 문제

  • 기준선은 중심지 먹이 찾기 알고리즘(central-place foraging algorithm, CPFA)이다.
  • 로봇은 둥지(nest)를 떠나 먹이를 찾는다. 찾으면 페로몬(pheromone) 지점을 서버에 남긴다.
  • 먹이가 몰린 곳은 여러 번 방문한다. 다른 곳은 한 번도 방문하지 않는다.
  • 방문한 점을 모두 서버에 보내면 점이 너무 많다. 서버가 매번 전부 훑으면 비용이 크다.
  • 교수님 석사 학생의 격자 방법은 경기장이 크면 칸이 커진다. 그러면 효율이 떨어진다.
  • 목표: 점을 더 효율적으로 정리해서 서버가 빈 곳을 빨리 찾게 한다. 그리고 점수를 올린다.

표 3. 과제의 실험 설정 (출처: 과제 PDF 3쪽, Table 1)
항목값
경기장 크기10 × 10 m
수집 구역(둥지) 반지름0.25 m
자원 수256
자원 분포(resource distribution)Random, Powerlaw, Clustered

  • 점수는 12분 동안 모은 먹이 수다. 교수는 팀끼리 점수를 비교해 성적을 매긴다.
  • 상자그림 하나는 50번 실행의 값이다. 기준선과 비교해 개선율(%)을 보고한다.
  • 반지름 0.25는 파일 값이다. 코드가 이 값에 1.82를 곱해 실제 반지름 0.456 m를 만든다 (코드 읽기에서 유도한 추정, inference). 결정 D-006이 이 읽기를 주 설정으로 정했다.

3 임무, 비전, 목표

표 4. 임무와 목표 (출처: PLAN.md 임무 블록, D-003에서 D-005)
줄내용
임무(mission)아무 로봇도 찾지 않은 곳을 찾아, 군집이 12분 동안 먹이를 더 모으게 한다. 군집과 경기장이 커져도 서버 비용을 작게 지킨다
비전(vision)한 페이지에 세 분포의 상자그림, 기준선 대비 개선율과 구간, 격자와 나란한 비용 대 경기장 크기 차트를 둔다. 실패마다 원인을 적는다
목표 G1 (11-21까지)벤치마크 판정. 경기장 80 m에서 B의 질의당 연산이 목록 전체 훑기의 1 % 이하이고, 같은 해상도의 격자보다 적다
목표 G2 (11-27까지)평가 실행 300개를 끝낸다. 확인을 통과한 실행 수와 분포별 개선 표를 낸다
목표 G3 (11-27까지)판정 파일 verdict.json을 커밋한다. 개선이 확인되지 않은 분포마다 원인 메모를 쓴다
연구 질문(research question) 1지도 기반 목표 선택이 분포마다 12분 수집량을 바꾸는가
연구 질문 2질의 비용이 방문한 넓이를 따르는가, 경기장 크기를 따르는가
연구 질문 3효과가 목표 선택에서 오는가, 출발 규칙 변경에서 오는가

통과 여부는 중요하지 않다. 미리 정한 절차를 지킨다. 실패하면 원인을 적는다 (저장소 규칙).

용어 부록

중심지 먹이 찾기 알고리즘(central-place foraging algorithm, CPFA)
로봇이 중앙 구역에서 나가 먹이를 찾고 다시 가져오는 알고리즘이다. 교수의 코드가 이것이다.
기준선(baseline)
비교의 기준이 되는 원래 알고리즘이다. 여기서는 교수의 CPFA 코드를 고치지 않고 그대로 쓴 것이다.
군집(swarm)
같은 규칙으로 움직이는 많은 로봇의 무리다. 여기서는 24대다.
서버(server)
둥지에 있는 중앙 저장소다. 로봇이 둥지에 올 때만 정보를 주고받는다.
둥지(nest)
로봇이 먹이를 내려놓는 중앙 수집 구역이다.
페로몬(pheromone)
먹이를 찾은 곳을 알리는 가상 신호다. 서버가 목록으로 가진다.
쿼드트리(quadtree)
정사각형을 네 칸으로 나누고, 필요한 곳만 더 잘게 나누는 자료 구조다.
격자(grid)
경기장을 같은 크기 칸으로 나눈 지도다. 칸마다 방문 횟수나 시각을 둔다.
시드(seed)
난수의 시작 값이다. 시드가 같으면 같은 시뮬레이션이 나온다.
상자그림(box plot)
값의 중앙, 사분위 범위, 이상값을 상자로 보이는 그림이다.
자원 분포(resource distribution)
먹이가 놓이는 방식이다. Random은 고르게, Powerlaw는 몇 큰 무더기와 많은 작은 무더기, Clustered는 몇 덩어리로 놓인다.
최소 기능 제품(minimum viable product, MVP)
단계마다 끝까지 도는 가장 단순한 버전이다. 1단계는 모의 데이터로, 2단계는 진짜 조각 하나로 돈다.
모의(mock)
진짜 결과가 아니라 모양을 확인하려고 만든 가짜 데이터다. 이름에 MOCK이 붙는다.
사전 등록(pre-registration)
실행 전에 판정 규칙을 파일로 적어 두는 일이다. 결과를 본 뒤에는 바꾸지 못한다.
