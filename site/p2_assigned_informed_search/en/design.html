Assigned Project 2 / method

Method: quadtree map and reservation

Result: the server keeps the visit records in a quadtree. A robot gets the nearest empty place as its target, and that place is reserved.

Why: the baseline sends a robot to a random point on a wall. So robots search the same places again.

Status: only the design is done. The method is not connected to the simulation. There are no measured results (section 9).

1 Problem and why

  • The assignment problem: up to 400,000 visited points pile up. A server that scans all of them each time pays a high cost (overview Table 2).
  • The limit of the grid method of the professor's MS student: when the arena is large, the cells are large.
  • Five facts from reading the baseline code shaped the design (source: baseline_code_map.md, DESIGN.md section 1).
Table 1. Facts of the baseline code and their effect on the design

1The "random location" is a point on a wall, not a uniform pointA new target may beat the wall
2The random branch runs only when the pheromone list is emptyWe must decide where the map branch fits (section 3, step 4)
3A robot with no target switches to search within about 1 m to 2 m (inference)A new target alone is never reached. We also change the departure rule (step 5)

Only one value is measured. One baseline run took 5.67 seconds and collected 245 items (STATUS.md). That is about 10 trips per robot (inference).

2 Structure

3 Five steps of one trip

  1. Step 1 Record
  2. Step 2 Upload
  3. Step 3 Store
  4. Step 4 Choose and reserve
  5. Step 5 Travel
Step 1 of 5

Record (robot side). While searching, log the position every 2 seconds. Skip a point in the same minimum cell as the last one. Also log the pickup position.

Why: fewer points can still tell visited from unvisited (assignment hint 3). The buffer is first-in first-out with 100 slots. 2 seconds is a start value (inference).

Step 2 of 5

Upload (robot side). On return to the nest, send the buffer to the server with the upload time. Then clear the buffer.

Why: it is the place where the baseline pushes the pheromone. We build no new communication path.

Step 3 of 5

Store (server side). Each cell keeps two times. t_last is the last visit time. t_res_until is the time the reservation ends.

Available time: avail_at = max(t_last + T_stale, t_res_until)

A cell is available when avail_at is at or before now.

Why: food respawns, so one visited bit is not enough. The start value of T_stale is infinity. 300 seconds is a tuning candidate (inference).

Step 4 of 5

Choose and reserve (server side). Find the available minimum cell nearest to the robot position. On a tie, take the lowest row, then the lowest column. The target is the center of that cell.

The decision order is site fidelity, pheromone, then map target. When a robot gets a map target, the cells within radius r_res are reserved for t_res seconds.

If no cell is available, fall back to the baseline random location and log it.

Why: the reservation keeps 24 robots from crowding into one cell. The professor's student grid has no reservation. Start values are 1.0 m and 60 seconds (inference).

Step 5 of 5

Travel (robot side). A robot with a map target skips the switch-to-search test that runs every 5 seconds. It drives to the target and then searches by random walk.

Why: with the test, the robot switches to search within 1 m to 2 m and never reaches the target (fact 3 in Table 1). We add a new flag isMapTarget, because reusing the old flag would also turn on the informed walk.

The question: which structure for the visit records lets the server find empty places cheaply?

  • Why B (D-010). It is complete like a fine grid. Its memory and query cost follow the visited boundary, not the arena size. That is the gap the professor names in the student grid.
  • Why not C first: it has no completeness bound. It draws more random numbers. A similar published method lost on Powerlaw. Yield scoring and the spiral stay as later tactics.
  • A is the fallback behind the same interface. At a 10 m arena, A and B give the same answers. The benefit is memory and query cost at large arenas.
  • The G1 verdict is judged at 80 m only (D-012). The map code of A and B is written but not built.

7 Experiment protocol

The question: does the new method collect more food than the baseline? The verdict rule is fixed before we see any result.

Table 5. Run sets (source: DESIGN.md section 6.1). Run counts are plans
SetArmsSeedsRunsPurpose
S0 invariancevendor, cpfa (switch off)3001 to 300530 + 2Equal when the switch is off?
S1 headroom and noisecpfa1001 to 103090branch shares, baseline noise
S2 tuningqmap candidates1001 to 1010270pick new parameters
S3 evaluation (primary)cpfa, qmap frozen2001 to 2050300verdict
S4 sensitivitycpfa, qmap frozen2001 to 2050300other reading of nest radius
S5 ablationqmap minus one part2001 to 2050at most 300which part gives the effect
  1. Evaluation seeds and tuning seeds never overlap. Both arms use the same 50 evaluation seeds.
  2. The score is the number collected at 720 seconds. Improvement is 100 · (mean_qmap − mean_cpfa) / mean_cpfa.
  3. One rule decides: the 95 % interval of a paired bootstrap that resamples the seed index 10,000 times.
  4. Each distribution gets its own verdict. Interval lower end above 0: improves. Upper end below 0: worse. Otherwise: not resolved.
  5. The Wilcoxon signed-rank test and the Holm adjustment are reported beside it. They do not decide.
  6. The verdict rule is pre-registered before evaluation. It does not change after the first evaluation run.

About 1,300 runs in total, one core, sequential, about 2.2 hours (an estimate from the smoke run, inference). A distribution with no improvement gets a root-cause memo. The criterion is never widened.

Hybrid candidate (D-018)

  • The hybrid rule of the spiral search page walks a spiral, then switches to a random walk when crowded. See the spiral search page.
  • This project adds that rule as one tuning candidate only. It sits next to the spiral tactic T4.
  • Its exact form is not fixed yet. It will be written into the design document and the tuning plan before the tuning pre-registration.
  • It is off by default. It turns on only if it wins on the tuning seeds. There is no evidence yet.
